# GeoTrader Sector — Sector Rotation & Relative Strength

The Streamlit sector-rotation script is now a static engine + dashboard,
matching the architecture of the main GeoTrader (F&O) terminal but as its
own independent project.

```
RAOSABINTEGRATION/                  <- your repo root (data lives here)
├── sectorial_index_data/           <- one JSON per sector index + the NIFTY benchmark
├── stockdata_D/                    <- one JSON per stock, daily candles
├── geotrader/                      <- the other project (F&O terminal) — untouched
└── sector/                         <- everything below lives here
    ├── engine.py                   <- calculation engine -> writes result.json
    ├── requirements.txt
    ├── sector_stocks.json          <- sector -> stock list mapping
    ├── index.html                  <- dashboard shell (structure only)
    ├── styles.css                  <- design system (shares GeoTrader's look)
    ├── app.js                      <- dashboard rendering logic
    ├── result.json                 <- generated by engine.py, read by app.js
    └── state/
        └── previous_rotation.json  <- persisted so the engine can detect
                                        rotation changes run-over-run
```

## 1. What changed from the Streamlit version

- All `streamlit`, `matplotlib`, and `fpdf` code is gone — no PDF export
  (that required an interactive server; use your browser's Print →
  Save as PDF on the page if you need a snapshot).
- Data source changed from **parquet** to your actual GitHub layout:
  **JSON** files under `sectorial_index_data/` (same mixed D/W/M-timeframe
  shape as the other GeoTrader project — the engine keeps only the daily
  rows) and `stockdata_D/` (flat daily OHLCV per stock, read locally
  instead of over HTTP from `Stock_Scanner_With_ASTA_Parameters`).
- The hardcoded `SECTOR_STOCKS` dict moved out of the script into
  `sector_stocks.json`, so you can edit sector membership without
  touching code.
- The date-picker / lookback-slider became a **precomputed snapshot**:
  the engine calculates everything for the latest available session (or
  an explicit `--date` for backtesting), and the "Sector vs NIFTY
  Performance" panel is precomputed at 6 standard lookbacks
  (10/15/20/30/45/60 sessions) so the lookback picker in the dashboard
  is instant with no server round-trip. If you need true ad-hoc
  backtesting with a free-form date picker, that would need the engine
  to run per-request rather than as a static snapshot — let me know if
  you want that mode instead.
- All indicator math is preserved: 1M/3M/6M returns, Leading / Improving
  / Lagging / Weakening classification, RS rank, the RRG coordinate
  system (RS vs NIFTY on x, 1M−3M momentum on y), the sector-weighted
  model portfolio, and the sector-leader stock scanner.
- Rotation-change alerts now persist across runs via
  `state/previous_rotation.json` (was `sector_rotation_state.csv` in the
  Streamlit version) — same diff logic, just JSON instead of CSV.

## 2. `sector_stocks.json`

```json
{
  "CNXIT": ["TCS", "INFY", "WIPRO", "HCLTECH", "..."],
  "BANKNIFTY": ["HDFCBANK", "ICICIBANK", "AXISBANK", "..."]
}
```
A stock can appear under more than one sector. This drives the
stock-level RRG panel and the sector-leader scanner. Without it, every
other panel (performance table, rotation table, RRG, top sectors, model
portfolio) still works — only the stock-level panels go empty.

## 3. Running the engine

```bash
cd sector
pip install -r requirements.txt
python engine.py
```

Looks for `sectorial_index_data/` and `stockdata_D/` one level up by
default (the repo root), and writes `sector/result.json`. All overridable:

```bash
python engine.py --root /path/to/RAOSABINTEGRATION --out /path/to/result.json
python engine.py --date 2026-06-15          # backtest anchor (uses data <= this date)
python engine.py --sector-map /path/to/sector_stocks.json
python engine.py --state /path/to/previous_rotation.json
```

Only the stocks referenced in `sector_stocks.json` are loaded from
`stockdata_D/` (not the whole folder), so a run stays fast even as that
folder grows.

### What it calculates
- Sector vs NIFTY performance at 10/15/20/30/45/60-session lookbacks
- 1M / 3M / 6M returns per sector, Leading/Improving/Lagging/Weakening
  classification, and an RS rank
- RRG coordinates: sector-vs-NIFTY (relative strength × momentum), and
  stock-vs-sector for every sector in `sector_stocks.json`
- Top strongest sectors by 1M return
- Rotation-change alerts (diffed against the previous run's state)
- A sector weight-adjusted model portfolio (Leading + Improving sectors,
  weighted by RS rank)
- A sector-leader scanner: stocks beating their own sector's 1M return,
  restricted to sectors currently in the model portfolio

## 4. Viewing the dashboard

`app.js` fetches `result.json` with `fetch()`, so serve over HTTP:

```bash
cd sector
python -m http.server 8000
```

Open **http://localhost:8000/index.html**. Refresh manually after
re-running the engine, or wait — it also auto-refreshes every 5 minutes.

### Deploying on GitHub Pages
Point GitHub Pages at the `sector/` folder the same way you would for
`geotrader/` — set Settings → Pages → source to `main` branch, folder
`/sector` (or link to `/sector/index.html` from elsewhere). Keep
`sector/result.json` committed and current, either by running the
engine locally and pushing, or with a scheduled GitHub Action (mirror
the `refresh.yml` pattern from the `geotrader/` project, swapping the
script path to `sector/engine.py --out sector/result.json`).

### Design
Same "Signal Deck" instrument-panel language as the main GeoTrader
terminal — dark hull, tabular monospace numerals, radar-sweep logo (in
signal-blue here instead of brass, to visually distinguish the two
dashboards) — plus one new signature element: a hand-rolled SVG **RRG
quadrant plot** (Leading / Improving / Lagging / Weakening, colour-coded
exactly like the original matplotlib chart) used for both the sector-
level and stock-level relative-rotation maps. No chart library — the
performance bars, RRG plots, and model-portfolio bars are all inline
SVG/CSS built from the same token set in `styles.css`.

### What's on it
- KPI strip: sectors tracked, Leading/Lagging counts, top sector, NIFTY
  1M return
- A rotation-change alert banner (only appears when something changed)
- Sector vs NIFTY performance bars with a live lookback picker and a
  NIFTY reference marker
- RRG-style sector map (quadrant scatter, sector-vs-NIFTY)
- Sector rotation table (1M/3M/6M returns, RS rank, rotation state)
- Top 5 strongest sectors
- Stock-level RRG — a sector dropdown swaps in that sector's stock scatter
- Sector weight-adjusted model portfolio bars
- Sector-based top stock scanner table
